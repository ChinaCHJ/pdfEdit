# PDF 编辑器（覆盖式改字）

打开 PDF 看到的就是原件页面本身 —— 点哪一行改哪一行，导出后除了改过的地方，其余部分和原件一模一样：位置、字体、图片、表格线、印章、页眉页脚全都不动。

不是「把 PDF 转成 Word 再重排」，而是**在原页面上做增量修改**。

## 能做什么

顶部五个模式：

**文字** — 点任意一行直接改。选中的行会覆盖上一层与背景同色的遮罩，原字被盖住。支持字号、加粗、8 种文字色、8 种字体、自动适应宽度、并入下一行、并入整段。

**批注** — 高亮、下划线、删除线、矩形、圈选、箭头、便签。矢量绘制，导出后仍然清晰。

**表单** — 自动识别 PDF 内已有的 AcroForm 输入框（浅蓝框），直接填写，勾选框可点。

**页面** — 每页下方有工具条：删除、左右旋转 90°、上移下移。还能插入空白页、合并另一个 PDF。**界面顺序就是导出顺序**。

**水印** — 文字、字号、透明度、角度，实时预览，一键应用到所有页。

## 不能做什么（重要）

说清楚边界，免得你下载完失望：

- **扫描件不行**。没有文字层的 PDF 点不出可编辑的块，需要先 OCR（本工具不含 OCR）。
- **导出后整页变成图片**，原件里的文字不再能搜索、复制、选中。只有你手动改过的那几行是真文字。这是「像素级保真」的代价。
- **文件会变大**，约 300 KB/页（每页存一张高分辨率底图）。
- **改动的段落会重排**。未改动的地方绝对不动，但你把一行改长之后，那一行会缩字号（可以关掉）或换行。
- **竖排文字会粘在旁边字段的块首**。比如发票左侧竖排的「购买方信息」逐字排列，第一个字会和同一行的「名称：」并进一个块。

## 技术原理

三层，Rust 只在中间：

```
浏览器（PDF.js 渲染页面 + 文字层编辑）
        ↓  POST /api/export  { 每页底图 + 覆盖层 }
Rust（axum）：组装 HTML
        ↓  调本机 Chrome/Edge --headless --print-to-pdf
输出 PDF
```

几个关键取舍：

**为什么不用 Rust 直接生成 PDF。** 中文断行、字体嵌入、字距调整，自己算是个无底洞，做出来还不如浏览器原生排版。代价是依赖本机装有 Chrome 或 Edge —— Windows 10/11 自带 Edge，所以实际无需额外安装。

**为什么导出后不能搜索。** 页面被转成了位图，只有改动行是真文字。要保留文字层就得按坐标重建整个文字流、处理字体子集缺失，难度高一个量级。这一版选择了「视觉保真优先」。

**文字块怎么切分的。** pdf.js 只按纵坐标分行，一行里离得再远也算同一行。所以先按纵坐标聚成视觉行，行内再按横坐标排序，间距超过 1.5 个字宽就切成独立的块 —— 否则发票表格里想改一个数字，整行都会变成可编辑。

**字体怎么认的。** pdf.js 的 `styles` 只给 `serif`/`sans-serif`，粒度不够。真实字体名在 `page.commonObjs` 里，但中文名是 UTF-8 字节被当成 latin-1 解出来的（`æ¥·ä½` 其实是「楷体」）。还原之后映射到系统字体，改出来的字才和原件像。

## 从源码构建

需要 Rust 1.85+（edition 2024）。

```bash
cargo run --release
```

开发时前端是从 `static/` 目录实时读的，改完刷新浏览器即可，不用重新编译。`PDF_EDITOR_NO_OPEN=1` 可以阻止自动打开浏览器。

打包发布用：

```bash
cargo build --release
# 产物就是 target/release/pdf-editor(.exe)，单文件，拷走即用
```

打 tag 会触发 GitHub Actions 自动构建三平台并发布 Release：

```bash
git tag v0.1.0 && git push origin v0.1.0
```
